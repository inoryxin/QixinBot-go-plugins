# QixinBot 插件开发手册（开发线 / 实验功能）

> 这份手册只适用于 **开发线构建**：`go build -tags dev ./cmd/bot`。
> 发行版（不带 `-tags dev`）**不包含休眠/定时唤醒**，请以 PLUGIN.md 为准。

## 6.1b 休眠（框架接管）：主动接入，默认开启

**休眠默认开启，但只作用于主动接入的插件。** 没接入的插件照旧自己定时、常驻内存。
控制台「休眠」页**只显示 manifest 里声明了 `idle_stop` 的插件**；界面里临时改的值不会让插件"假接入"。

**接入方式**：manifest 里同时声明

```toml
idle_stop = "30m"          # 闲置 30 分钟就停进程

[[schedule]]
id = "daily"
cron = "0 9 * * *"         # 定时交给框架，睡了也能到点叫醒
```

**不接入**：保持原来的写法（自己 `setInterval`），框架不碰它。

**接管后框架负责**：到点唤醒（cron）、命令唤醒、能力/工具调用唤醒、
事件（需 `events` 订阅）、手动运行任务。样例：`ncm-saying`（网抑云，每天 9 点一条）。

**总开关默认开启**，位置在控制台独立的「休眠」页；关掉后所有接入插件都恢复常驻。

**允许休眠的前提**（框架会检查，不满足就拒绝并警告）：

- 有 `[[schedule]]`（定时交给框架，睡了也能被叫醒），**或**
- 有 `provides` 能力（别的插件/接口会调用它），**或**
- 有 `events` 事件订阅（对应事件到达时会唤醒它）

**只有命令的插件需要 `idle_ok = true`**（怕内部 setInterval 被睡掉）；
有 `[[schedule]]` / `provides` / `events` 的插件可以直接休眠，这三类入口都会唤醒它。

确有把握的可以用 `idle_ok = true` 显式声明“我可以安全休眠”（仅命令类插件需要），
框架会拒绝休眠并提示"插件没有唤醒途径"。

```toml
[[schedule]]
id = "tick"
cron = "{{minute}} {{hour}} * * {{weekday}}"   # 设置改了自动重排
```

**唤醒途径**：匹配命令 / 调用能力 / 定时到点（含 cron 模板）/ 手动重载。


低频插件（订阅、抽卡、天气）没必要一直占内存：

```toml
# 闲置 1 小时就停进程；有人用再拉起
idle_stop = "1h"
```

**行为**：

- 框架每 30 秒检查一次，超过 `idle_stop` 没活动就停进程（状态显示 `idle`）
- **收到它声明的命令** / **有人调它的能力** / **定时任务到点** → 自动唤醒
- **界面可覆盖**：插件列表「闲时(分)」列：
  - 填 0 = **明确不休眠**（覆盖清单）
  - 留空 = 用清单里的 `idle_stop`
  - 存 `data/idle.json`
- **定时任务是框架级**：插件被回收后，它的 cron 任务仍然在框架里跑，到点先唤醒再执行
- 唤醒是冷启动，慢 1~2 秒；热路径插件（AI 聊天、关键词回复）别开
- 没匹配到它命令的群消息**不会**唤醒它（否则回收没意义）

**适合**：cngal / fortune / weather / 订阅播报 / 定时任务类
**不适合**：ai-chat、keyword-reply、trigger、bilibili 这类随时要响应的

## 6.1c 定时任务（开发线）

开发线里定时由框架接管，插件只声明 + 实现 `run_task`：

```toml
[[schedule]]
id = "check-updates"
every = "5m"
description = "检查更新"
```

```js
async run_task({ task }) {
  if (task === 'check-updates') await checkAndPush()
  return {}
}
```

cron 模板（`{{key}}` 会替换成设置值）：

```toml
[[schedule]]
id = "weekly"
cron = "{{minute}} {{hour}} * * {{weekday}}"
```

- 设置保存后框架立刻重排，不用重启
- 停机错过 24 小时内的任务，启动时会补跑一次
- 任务页支持暂停/恢复/手动触发，`tasks.json` 落盘
- 只有开发线注册调度；**发行版必须插件自己 `setInterval`**

## 实验功能的边界

- 只有开发线开启：闲置回收、休眠页、"到点唤醒睡着的插件"
- 发行版插件必须**自己管理定时**（`setInterval` / 进程内定时器），并保持常驻
- 开发线验证过的功能如果要进发行版，需要先去掉对休眠的依赖，再合并
